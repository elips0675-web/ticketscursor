# 00 — Роль, границы, запреты

Ты — AI-агент production-репозитория **tickets-service-desk** (корпоративный Service Desk).
Стек: React 19 + TypeScript 5 (strict) + Vite 8 + Tailwind 4 + shadcn/ui + TanStack Query + react-i18next / Express 5 + Prisma + MySQL 8 + Socket.IO.

## Единственные источники правил

| Файл | Что там |
|---|---|
| `AGENTS.md` | правила 1–21: архитектура, гейты, канон журналов, DoD |
| `prompts.md` | шаблоны промтов, «Универсальный промт этапа» |
| `Что-доделать.txt` | бэклог — только ОТКРЫТЫЕ пункты (зеркало в `test-analysis/`) |
| `Что сделано.txt` | хроника закрытых этапов — историю не переписывать |
| `PLAYBOOK.md`, `TECHNICAL.md` | эксплуатация и устройство |

Правила здесь **не дублируются**. Если этот файл расходится с `AGENTS.md` — прав `AGENTS.md` (правило 21).

## Границы задачи

1. Работай только с пунктом, который явно выбрал пользователь. Не начинай соседние этапы, не делай «рефакторинг заодно».
2. Этапы 69–71 не начинать, пока не закрыты 66–67 (очередь — в `Что-доделать.txt`).
3. Новый экран/модуль — только за feature flag (`useFeature()`), дефолт **off** (правило 12).
4. Любое утверждение о коде — с `file:line`. Без ссылки правка не принимается (правило 14).
5. Сначала исправить причину бага, потом закрепить тестом (правило 15).

## Абсолютные запреты

- `any`, `as any`, `// @ts-ignore`, `@ts-expect-error` без обоснования в отчёте.
- `npm install` / `npm update` / правка `package-lock.json` без прямого разрешения.
- `git reset --hard`, `git checkout -- .`, `git clean`, force-push, удаление файлов, `git push` без подтверждения.
- Правка `.env`, `auth.json`, секретов, `server/uploads/**`.
- Правка журналов `.txt` через PowerShell — только node-скриптами (`fs.readFileSync`/`writeFileSync`, utf8), правило 19.
- Придуманные команды и скрипты: только те, что есть в `package.json` / `scripts/`.
