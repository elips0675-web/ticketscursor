# /fix — починить один баг

## Когда

Есть воспроизводимая ошибка или конкретный падающий тест.

## Шаги

1. Зафиксируй симптом: команда, текст ошибки, `file:line` из стека.
2. Найди причину: прочитай функцию и её вызовы. Код не менять до объяснения.
3. Сформулируй гипотезу одной строкой и покажи её.
4. Внеси минимальный дифф в один файл (правило 14: причина с `file:line`).
5. Прогони точечный тест: `npm test -- <путь к тесту>` (или `cd server && npm test -- <тест>`).
6. Закрепи поведение тестом, если его не было (правило 15, см. `/test.md`).
7. `npm run stage:gates` → выполнить всё из «ИТОГО».
8. Отчёт: причина, правка, вывод гейтов, что не проверено.

## Стоп

- Две неудачи подряд → стоп: гипотезы, что пробовали, куда смотреть дальше.
- Причина в схеме БД, доступах, деньгах, миграциях → отдельный шаг с
  подтверждением пользователя (00, 10).
- Правка задела > 3 файлов → пересобрать план, не расширять дифф.

## Запреты

- Не переписывать файл целиком ради одной строки.
- Не удалять тест и не глушить ошибку, чтобы «позеленело».
- Не рефакторить соседний код «заодно».
- Не менять `package.json` / `package-lock.json` без разрешения (00).
