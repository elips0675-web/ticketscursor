# /test — тест на существующее поведение

## Когда

Нужно закрепить поведение, которое уже работает, или закрыть пробел покрытия.

## Шаги

1. Найди существующий тест рядом: `src/test/<Component>*.test.tsx` или
   `server/src/**/*.test.*`. Повтори его стиль, моки (MSW) и структуру.
2. Прочитай тестируемую функцию целиком: входы, выходы, ошибки, границы.
3. Напиши один тест на один сценарий — успех, граница или ошибка.
4. Обязательные негативные сценарии — правило 17: без прав → 403; просроченный
   токен → 401; невалидное тело → 400; повтор → нет дубля; недоступный
   Redis/SMTP/S3 → деградация, а не 500.
5. Запусти только новый тест, затем файл целиком.
6. Если менял тесты — перегенерируй инвентарь (правило 10) и прогони
   `npm run check:docs`.
7. `npm run stage:gates` → всё из «ИТОГО».

## Стоп

- Нет тестового окружения или нужна живая MySQL/секреты → не выдумывать,
  записать «не покрыто» и согласовать отдельный шаг.
- Тест требует новой зависимости → разрешение пользователя (00).

## Запреты

- Не писать тест, который повторяет реализацию.
- Не ослаблять существующие проверки и пороги покрытия.
- Не добавлять `skip`/`todo` без причины и даты в отчёте.
