# /review — ревью diff по фактам

## Когда

Есть готовый diff или PR, нужно найти риски, а не пересказать изменения.

## Шаги

1. Получи diff: `git diff` / `git diff --cached` / `git show <sha>`.
   Не читай весь репозиторий.
2. Для каждого изменённого файла прочитай контекст вокруг правки.
3. Проверь по пунктам: логика, границы, ошибки, безопасность, данные, тесты,
   идемпотентность (20, п. 4), негативные сценарии (правило 17).
4. Каждое замечание — с `file:line` и цитатой. Без цитаты — это не замечание.
5. Раздели: «блокер», «желательно», «вопрос».
6. Отчёт: вердикт, замечания, что не проверено.

## Стоп

- Diff больше 10 файлов → ревью по частям или сузить.
- Затронуты деньги, доступы, миграции, секреты → отдельный шаг с пользователем.

## Запреты

- Не пересказывать diff.
- Не предлагать «переписать всё».
- Не выдавать стилистику за блокер.
- Не править код в рамках ревью без явной просьбы.
