# Переключение «локально ↔ облако» (Cline + OpenCode)

> Один скрипт переключает провайдера и модель сразу в двух местах:
> **Cline** (VS Code) и **OpenCode** (этот репозиторий).
> Проверено на машине RTX 3060 12 ГБ / 16 ГБ ОЗУ, 30.10.2026.

---

## 1. Профили

| Профиль | Cline (VS Code) | OpenCode | Когда |
|---|---|---|---|
| `local` | Ollama `servicedesk-qwen` (7B Q4_K_M, ctx 16k) | `ollama/servicedesk-qwen:latest` | обычная работа без сети: один файл за подход |
| `local-q5` | Ollama `servicedesk-qwen-q5` (7B Q5_K_M, ctx 16k) | `ollama/servicedesk-qwen-q5:latest` | то же, но чуть качественнее: факт 6.5 ГБ VRAM, 100 % GPU |
| `local14` | Ollama `servicedesk-qwen-14b` (14B Q4_K_M, ctx 8k) | `ollama/servicedesk-qwen-14b:latest` | сложнее, но нужно ~10 ГБ VRAM: закройте браузер |
| `cloud` | Ollama `gpt-oss:120b-cloud` | `opencode/deepseek-v4.1-flash-free` | эскалация: многофайловые задачи, ревью, миграции |
| `cloud-ollama` | Ollama `gpt-oss:120b-cloud` | `ollama/gpt-oss:120b-cloud` | одно облако Ollama в обоих инструментах |

`cloud` — самый практичный вариант: Cline идёт через уже выполненный `ollama signin`,
а OpenCode использует бесплатную облачную модель OpenCode (ключ не нужен).
`local` — профиль по умолчанию в `opencode.json`.

Переопределить облачные модели можно переменными окружения (задать **до** запуска
`opencode`/скрипта, в том же процессе):

```
set AI_CLOUD_OLLAMA_MODEL=gpt-oss:120b-cloud
set AI_CLOUD_OPENCODE_MODEL=opencode/deepseek-v4.1-flash-free
set OLLAMA_URL=http://127.0.0.1:11434
```

### Квант: Q4_K_M или Q5_K_M

- **Q4_K_M** (`local`) — 4.7 ГБ весов, максимум скорости и запаса VRAM, контекст 16k.
- **Q5_K_M** (`local-q5`) — 5.4 ГБ весов, +~0.7 ГБ, качество чуть выше (заметнее
  на следовании инструкциям и tool-call), скорость ниже на ~10 %. На 3060 12 ГБ
  при 16k всё ещё 100 % GPU (~6.5 ГБ).
- **14B** — только Q4_K_M: Q5 (~10.5 ГБ + KV) на 12 ГБ уже не влезает.

Правило: для агента контекст важнее последних 1–2 % качества. Нужен 32k — берите
Q4_K_M; хватает 16k и нужна точность формулировок — Q5_K_M.

Модель `servicedesk-qwen-q5` собрана из `.ai/Modelfile-q5`:

```bat
ollama pull qwen2.5-coder:7b-instruct-q5_K_M
ollama create servicedesk-qwen-q5 -f .ai/Modelfile-q5
ollama show servicedesk-qwen-q5 --modelfile | findstr /i "num_ctx"
```

## 2. Команды

Из `cmd` в корне репозитория:

```bat
.ai\switch-ai.bat status
.ai\switch-ai.bat local
.ai\switch-ai.bat local-q5
.ai\switch-ai.bat local14
.ai\switch-ai.bat cloud
.ai\switch-ai.bat cloud-ollama
```

Проверить, что изменится, ничего не записывая:

```bat
.ai\switch-ai.bat cloud --dry-run
```

Только OpenCode (VS Code можно не закрывать) или только Cline:

```bat
.ai\switch-ai.bat local --opencode-only
.ai\switch-ai.bat local --cline-only
```

Из PowerShell то же самое (Node лежит в Laragon, в новых терминалах VS Code он уже в PATH):

```powershell
node .ai/ai-profile.mjs status
node .ai/ai-profile.mjs cloud
```

`switch-ai.bat` сам подставляет `C:\laragon\bin\nodejs\node-v22\node.exe`.

## 3. Что именно меняется

### OpenCode — `opencode.json`

Скрипт правит только три вещи, остальное сохраняет:

- `model` — модель по умолчанию для новых сессий;
- `default_agent` — `local` (без сети, 10 шагов) или `cloud`;
- блок `providers.ollama.models` — явные описания локальных сборок и облачного тега
  (нужны, потому что облачные `-cloud` модели не попадают в автодискавери Ollama).

Перед записью делается `opencode.json.bak-<дата>`.

Важно:

- конфиг подхватывается **без перезапуска** OpenCode;
- но **уже открытая сессия** хранит выбранную модель отдельно — переключите её
  через `/models` или начните новую сессию;
- проверить список: `opencode models` (в корне репозитория). Если `opencode` нет в
  PATH (на этой машине CLI идёт в комплекте с приложением), используйте `/models`
  в самом OpenCode либо
  `%APPDATA%\ai.opencode.desktop\cli\<версия>\opencode-cli.exe models`.

### Cline — `state.vscdb`

Cline хранит провайдера и модель не в `settings.json`, а в globalState VS Code
(`%APPDATA%\Code\User\globalStorage\state.vscdb`, ключ `saoudrizwan.claude-dev`).
Скрипт обновляет:

```
apiProvider, apiModelId,
planModeApiProvider, actModeApiProvider,
planModeApiModelId, actModeApiModelId,
ollamaModelId, ollamaBaseUrl, ollamaApiOptionsCtxNum,
planModeOllamaModelId, actModeOllamaModelId
```

Авто-одобрение, чекпоинты и остальные настройки **не трогаются**.

Требования:

1. **Закройте VS Code** — иначе скрипт откажется писать (VS Code перезапишет
   состояние при выходе). Обойти можно `--force`, но это риск.
2. После записи откройте VS Code заново: Cline читает состояние при старте.
3. Проверка: Cline → шестерёнка → **API Configuration**.
4. Перед записью делается `state.vscdb.bak-<дата>` рядом с базой.

## 4. Облако: что должно быть готово

### Ollama Cloud (Cline и профиль `cloud-ollama`)

Вход выполняется один раз:

```bat
ollama signin
```

Проверка живого тега (не угадывать!):

```bat
ollama show gpt-oss:120b-cloud
```

Факт на 30.10.2026 (эта машина, аккаунт уже авторизован):

| Тег | Статус |
|---|---|
| `gpt-oss:120b-cloud` | ✅ работает, 131k контекста, tools + thinking |
| `gemma4:31b-cloud` | ✅ работает, 262k контекста, tools + vision (Free plan) |
| `deepseek-v4.1-flash:cloud` | ⚠️ тег есть, но запрос вернул **402 Payment Required** (нужны кредиты) |
| `deepseek-v4-pro:cloud` | ⚠️ тег есть, кредиты не проверялись |
| `qwen3-coder:480b-cloud` | ❌ **отозван 15.07.2026** — в комплекте `3060OllamaClineOpenCode-main` этот тег устарел |

Если тег отозван, Ollama сама подскажет замену в тексте ошибки. Меняется только
имя модели — профиль и скрипт остаются.

### OpenCode (профиль `cloud`)

`opencode/deepseek-v4.1-flash-free` — бесплатная модель облака OpenCode, отдельный
ключ не нужен (аккаунт OpenCode уже подключён). Проверка:

```bat
opencode models
```

### DeepSeek / OpenRouter напрямую (необязательно)

Скрипт их не настраивает: без ключа это мёртвый профиль. Если понадобится:

```bat
setx DEEPSEEK_API_KEY "sk-..."
setx OPENROUTER_API_KEY "sk-or-..."
```

и подключить провайдера в OpenCode через `/connect`. Ключи **не** кладите в репозиторий
и не вставляйте в `opencode.json`.

## 5. Дисциплина облачного режима

- Авто-одобрение записи файлов и команд в Cline в облаке **держите выключенным**:
  ошибка дорогой модели на большом репозитории стоит денег и ломает гейты.
- В облако не отправляются `.env`, `auth.json`, дампы БД, выгрузки пользователей,
  переписка из `messages/chats` и скриншоты с реальными ПДн.
- Перед вставкой лога в облачный чат прогоните его через очистку (email, UUID,
  телефоны, ключи) — рецепт в `E:\3060OllamaClineOpenCode-main\05-Облако-и-DeepSeek.txt`.
- Коммит делает человек. Локальная модель `git add/commit/push` не выполняет.

## 6. Откат

Скрипт оставляет бэкапы:

```
opencode.json.bak-2026-10-30T12-34-56
%APPDATA%\Code\User\globalStorage\state.vscdb.bak-2026-10-30T12-34-56
```

Вернуть вручную: закройте VS Code, скопируйте `.bak` поверх исходного файла.
Для OpenCode достаточно вернуть старый `opencode.json` (или удалить его — тогда
действует глобальный конфиг OpenCode).

---

## 7. Если что-то не так

| Симптом | Причина / решение |
|---|---|
| `VS Code запущен: настройки Cline не записаны` | закройте VS Code и повторите; либо `--force` (на свой риск) |
| Cline после переключения всё ещё на старой модели | VS Code не перезапускали; Cline читает state при старте |
| OpenCode показывает старую модель | модель закреплена за открытой сессией: `/models` или новая сессия |
| `Model unavailable: ollama/...` | модели нет в Ollama: `ollama list`, при необходимости `ollama pull` / `ollama create` |
| `402 Payment Required` на `-cloud` | закончились кредиты Ollama Cloud; возьмите `gemma4:31b-cloud` (Free) или локальную модель |
| Ollama не отвечает | `ollama serve`, затем `ollama ps` — `PROCESSOR` должен быть `100% GPU` |
| 14B тормозит / ушла на CPU | закройте браузер и Docker; `ollama stop servicedesk-qwen-14b`; вернитесь на `local` |
| `node:sqlite недоступен` | нужен Node 22.5+; запускайте через `.ai\switch-ai.bat` (Laragon) |

## 8. Связь с комплектом 3060

Комплект `E:\3060OllamaClineOpenCode-main` задаёт ту же схему (локально ↔ облако),
но переключает вручную: профили Cline или два workspace. Здесь это автоматизировано
одним скриптом. Правила проекта (`.clinerules`, `AGENTS.md`) при переключении не
меняются — меняется только модель.
