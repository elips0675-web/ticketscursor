## 2. Настройка Cline в VS Code (руками, 2 минуты)

Расширение `saoudrizwan.claude-dev` уже установлено (v4.1.26). Настройки провайдера хранятся в глобальном состоянии VS Code, поэтому их нужно один раз выставить в UI:

1. Откройте панель Cline → иконка шестерёнки → **API Configuration**.
2. **API Provider**: `Ollama`.
3. **Base URL**: `http://localhost:11434`.
4. **Model ID**: `servicedesk-qwen` (или `servicedesk-qwen-14b` для сложных задач).
5. **Context Window**: `16384` — должно совпадать с `num_ctx`, иначе Cline будет слать больше, чем модель принимает, и Ollama начнёт резать/тормозить.
6. Отключите «Use different models for Plan/Act», если включено: локальная модель одна.

### ⚠️ Авто-одобрение — сейчас небезопасно

В обнаруженных настройках Cline включено авто-одобрение **всех** действий, включая `editFiles` и `executeAllCommands`. Для локальной 7B-модели это прямой риск: она может массово переписать файлы или выполнить `npm install`/`git reset`.

Рекомендуемая конфигурация (Cline → Settings → Auto-approve):

| Действие | Разрешить |
|---|---|
| Read files / List / Search | ✅ да |
| Edit files | ❌ нет (подтверждать вручную) |
| Execute commands | ❌ нет (либо только safe-команды) |
| Use browser / MCP | ❌ нет |

Включайте запись и команды только когда убедились, что модель стабильно проходит гейты.

## 2.1. Переключение «локально ↔ облако» (одна команда)

Профили переключаются сразу в Cline и OpenCode:

```bat
.ai\switch-ai.bat status          :: что сейчас
.ai\switch-ai.bat local           :: 7B Q4_K_M / 16k, офлайн
.ai\switch-ai.bat local-q5        :: 7B Q5_K_M / 16k, чуть качественнее
.ai\switch-ai.bat local14         :: 14B / 8k
.ai\switch-ai.bat cloud           :: Cline — gpt-oss:120b-cloud, OpenCode — free cloud
.ai\switch-ai.bat cloud-ollama    :: gpt-oss:120b-cloud в обоих
```

- Cline: **закройте VS Code** — скрипт пишет в `state.vscdb` и делает бэкап.
- OpenCode: `opencode.json` подхватывается без перезапуска, но открытая сессия
  модель не меняет — `/models` или новая сессия.
- Подробности, живые облачные теги и откат: `.ai/ПЕРЕКЛЮЧЕНИЕ-МОДЕЛЕЙ.md`.

Факт на 30.10.2026: `qwen3-coder:480b-cloud` из комплекта **отозван 15.07.2026**;
работают `gpt-oss:120b-cloud` и `gemma4:31b-cloud`, а `deepseek-v4.1-flash:cloud`
пока отдаёт 402 (нужны кредиты). Тег в профиле меняется одной переменной
`AI_CLOUD_OLLAMA_MODEL` или правкой `.ai/ai-profile.mjs`.

## 3. Правила агента: `.clinerules/`

Cline автоматически читает папку `.clinerules/` в корне и подмешивает её в системный промт.

| Файл | Содержание |
|---|---|
| `00-role.md` | роль, границы задачи, абсолютные запреты (`any`, `npm install`, `git reset`, правка секретов) |
| `10-gates.md` | таблица «изменённые файлы → обязательные гейты», смысл каждого гейта |
| `20-workflow.md` | цикл работы, негативные сценарии, идемпотентность, миграции, DoD, формат отчёта |
| `30-context-map.md` | карта репозитория и бюджет 16k токенов: что не читать целиком |

Важно: правила **не скопированы** из `AGENTS.md`, а ссылаются на него — это требование правила 21 проекта («правила только в AGENTS.md, промты ссылаются»). Поэтому при изменении правил правится `AGENTS.md`, а `.clinerules` остаётся тонким слоем «как работать».

## 5. Контроль VRAM (RTX 3060 12 ГБ)

- 7B / 16k → ~5.8–6.5 ГБ: комфортно, остаётся Windows + VS Code + браузер.
- 14B / 8k → ~9.5–10.5 ГБ: только когда браузер закрыт; при нехватке Ollama сама выгрузит часть слоёв на CPU и скорость упадёт в 5–10 раз.
- Проверка: `ollama ps` — колонка `PROCESSOR` должна быть `100% GPU`.
- Освободить VRAM: `ollama stop servicedesk-qwen-14b`.
- Не держите открытыми Chrome с десятками вкладок и Docker Desktop одновременно с 14B.

## 5.1. Node / npm в терминале (проверено 29.10.2026)

На этой машине **Node нет в системном PATH**, он лежит в Laragon: `C:\laragon\bin\nodejs\node-v22` (`v22.23.4`, npm `10.9.9`). Плюс политика выполнения запрещает `npm.ps1`, поэтому в PowerShell `npm` не работает.

Что уже сделано в `.vscode/settings.json`:

```jsonc
"terminal.integrated.defaultProfile.windows": "Command Prompt",
"terminal.integrated.env.windows": { "PATH": "C:\\laragon\\bin\\nodejs\\node-v22;${env:PATH}" }
```

Итог: в новых терминалах VS Code (в т.ч. в терминале, который открывает Cline) `npm run ...` работает.

Альтернатива, если хотите остаться в PowerShell (один раз, для текущего пользователя):

```powershell
Set-ExecutionPolicy -Scope CurrentUser -ExecutionPolicy RemoteSigned
```

Проверка: `node -v && npm -v` → `v22.23.4` / `10.9.9`.

## 6. Первый запуск (по шагам)

1. Убедитесь, что Ollama запущена: `ollama ps` (если ошибка — `ollama serve`).
2. Откройте папку `E:\Tickets Cursor nout\repo` в VS Code как рабочую (workspace root должен быть корнем репозитория — иначе `.clinerules` не подхватится).
3. Настройте Cline по разделу 2, отключите авто-одобрение записи/команд.
4. В терминале: `npm run stage:preflight` — быстрые гейты ДО работы. Красный preflight = сначала починить базу.
5. Скопируйте промт из `.ai/Промт-1-P1-14.md` в чат Cline.
6. После ответа модели: проверьте дифф, запустите `npm run stage:gates`, затем полный `npm test`.
7. Закоммитьте сами: `git add -A && git commit -m "..."` (пусть агент не пушит без вашего подтверждения).

## 7. Если что-то пошло не так

| Симптом | Причина / решение |
|---|---|
| Ответы — «не могу понять запрос» | Кириллица через `echo | ollama run` в PowerShell ломается. Тестируйте через API (раздел 1) или в самом Cline |
| Модель не видит правила | Открыта не та папка; `.clinerules` лежит не в корне; нужно перезапустить задачу Cline |
| Cline «забывает» про гейты | Напомните: «Ты нарушил правило из `.clinerules/10-gates.md`. Запусти `npm run stage:gates` и покажи вывод» |
| Модель режет ответ | `num_predict 4096` в Modelfile; для длинных файлов просите фрагментами |
| Гейт `check:docs` падает после правки журнала | Правили `.txt` через PowerShell → переделайте node-скриптом и синхронизируйте `test-analysis/` |
| Модель предлагает новый этап/рефакторинг | Стоп-фраза: «Нарушение `.clinerules/00-role.md`: только выбранный пункт бэклога. Вернись к задаче» |
| Тормозит всё | `ollama stop <model>`, закройте браузер; проверьте `ollama ps` — не ушла ли модель на CPU |
| `npm : Имя "npm" не распознано` | Node нет в PATH → откройте новый терминал (настройки воркспейса подхватываются) или добавьте `C:\laragon\bin\nodejs\node-v22` в PATH |
| `выполнение сценариев отключено` (npm.ps1) | Профиль терминала → Command Prompt, либо `npm.cmd`, либо `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned` |

## 8. Ограничения локальной 7B (честно)

- Держит в голове ~3–5 файлов; на задачах «больше одного модуля» качество падает — дробите.
- Склонна «улучшать» лишнее: жёстко ограничивайте дифф.
- Плохо считает покрытие и не умеет читать 300-КБ журналы: давайте ей вывод команд, а не файлы.
- Для задач уровня «Этап 67 целиком» берите 14B или внешнюю модель; локальная — для изолированных пунктов (тесты, типы, локаторы, мелкие баги).
