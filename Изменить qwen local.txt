- Как универсальный чек-лист — **6/10**: структура «4 этапа» разумная.
- Как план конкретно для этого репозитория — **3/10**: около 60% пунктов уже сделаны, часть неприменима, часть содержит фактические ошибки.
- Выполнять файл буквально нельзя: получим работу над уже закрытыми задачами и миграции ради миграций.
- Главный дефект: план писался без чтения кода. Он не знает реального покрытия, структуры тестов, CI и текущих гейтов.

## 7. Гейты и Definition of Done

Перед коммитом / в CI:

```bash
npm run check:docs
npm run lint
npm run type-check
npm test
cd server && npm test
npm run build
node check-console.mjs
npx playwright test
```

DoD на фичу (правила репозитория):
1. Feature flag через `useFeature()`, дефолт off.
2. Тесты (клиент + сервер), негативные сценарии и идемпотентность.
3. i18n ru/en.
4. `check-console.mjs` → `ALL OK`, `[OK/RU]` на страницах обхода.
5. Актуальный инвентарь тестов (`test-analysis/test-inventory.json`).
6. Синхронизация доков (`check-doc-sync`).
