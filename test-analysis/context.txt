## Проблемы (решённые)

### MySQL не запущен → 500 на всех страницах
- **Причина**: Laragon был запущен, но MySQL-сервис не стартовал
- **Решение**: перезапущен Laragon → MySQL поднялся
- **Дополнительно**: `deleted_at`, `last_active`, `event_outbox` не существовали в БД — добавлены вручную

### Prisma client не синхронизирован со схемой
- **Причина**: после мержа 10 коммитов (soft-delete, outbox) `prisma generate` не был запущен
- **Решение**: `npx prisma generate` + ALTER TABLE для добавления колонок

## SLA Escalation — реализация (v1.5.0)

**Что делает:**
- При просрочке SLA (due_at истёк) и включённой эскалации — автоматически повышает приоритет тикета
- Уровни: low → medium → high → critical (повышение на 1 шаг за каждый интервал эскалации)
- Настраивается в админке: включение/выключение, шаг эскалации в часах

**Backend:**
- Миграция `server/migrations/20260721_sla_escalation.js` — `escalated_at` + `escalation_level` в tickets
- Prisma модель: `escalated_at DateTime?`, `escalation_level Int @default(0)`
- `server/src/background.js` — `runSlaCheck()` расширена: проверяет каждый просроченный тикет на необходимость эскалации
- `server/src/notify.js` — новая функция `notifySlaEscalated()`: уведомления (in-app + email + Telegram), аудит-лог, WebSocket `ticket:sla:escalated` в комнату тикета
- Настройки `SLA_ESCALATION_ENABLED` (true/false) и `SLA_ESCALATION_HOURS` (число) через AllowedSettings

**Frontend:**
- `TicketDetail.tsx` — бадж "Эскалация ур. N" (красный, AlertTriangle) при escalationLevel > 0
- `AdminSettings.tsx` — поля `slaEscalationEnabled`, `slaEscalationHours` в секции ticketSettings
- i18n ключи: `tickets.escalated`, `admin.slaEscalationEnabled`, `admin.slaEscalationHours`

**Что делает:** карточка «Время» в TicketDetail для agent/senior_agent/admin/super_admin — ручной ввод времени по тикету + таймер (start/stop) с живым подсчётом.

**Backend:**
- Миграция `server/migrations/20260918_time_tracking.js` — таблицы `time_entries` (ticket_id, user_id, minutes, description, entry_date) и `ticket_timers` (ticket_id, user_id, started_at), FK, индексы
- Prisma: модели `TimeEntry`, `TicketTimer` (+ relation на Ticket/User), `tickets.time_spent_minutes Int @default(0)`
- `server/src/services/time.service.js` — `createTimeEntry`, `getTicketTime` (entries + totalMinutes + totalEntries + activeTimer), `startTimer`/`stopTimer` (стоп пишет entry из потраченных минут, ноль не сохраняется), `deleteTimeEntry` (владелец или senior_agent+), пересчёт `time_spent_minutes` на постоянный инвариант
