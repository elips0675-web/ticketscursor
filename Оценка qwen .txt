🟡 Зоны роста (Что можно улучшить)
1. Нагрузочные тесты (Load Tests)
В tickets.k6.js и chat.k6.js используется POST /api/auth/dev-login.
Риск: Вы тестируете бизнес-логику, но обходите реальную систему авторизации (LDAP/БД). Если в реальном login будет узкое место (например, медленный хэш пароля), k6 этого не покажет.
Совет: Добавьте сценарий, где 10% виртуальных пользователей используют "тяжелый" реальный логин, а 90% — переиспользуют токен.
2. Безопасность и Nginx
В docker-compose.yml Nginx слушает 443 порт, но в nginx/default.conf нет настройки SSL-сертификатов.
Совет: Для продакшена добавьте генерацию Let's Encrypt (например, через certbot в отдельном контейнере или nginx-proxy-acme) или пробрасывайте уже готовые сертификаты через volumes.
3. Оптимизация GitHub Actions
В джобе playwright вы устанавливаете браузеры: npx playwright install --with-deps chromium. Это занимает 1-2 минуты.
Совет: Используйте кэширование для Playwright и node_modules, чтобы ускорить CI.
В джобе playwright сервер стартует фоном (node src/index.js &), но нет ожидания его готовности (healthcheck). Vite и Playwright могут запуститься раньше, чем БД и сервер поднимутся, что приведет к flaky-тестам. Добавьте sleep 5 или скрипт ожидания curl --retry.
4. API E2E тесты
scripts/test-e2e-api.js написан на чистом fetch. Это круто и быстро, но lacks of assertions library.
Совет: Если тестов станет больше, рассмотрите использование vitest для API тестов или хотя бы добавьте простую обертку для красивых отчетов (например, console.table для summary).
