Оценка проекта Service Desk
На основе предоставленных файлов (README, context.txt, Что-доделать.txt, AGENTS.md, CHANGELOG.md, тесты, инфраструктура, package.json) можно сделать комплексную оценку.

Общая оценка: 7.5 / 10
Проект представляет собой зрелый, многофункциональный Service Desk с современным стеком, широким покрытием тестами и продуманной архитектурой. Однако есть критичные проблемы в инфраструктуре (CI/Docker) и заметный технический долг, которые не позволяют поставить более высокую оценку.

Сильные стороны
Современный и продуманный стек — React 19, Vite 8, Express 5, Prisma, Socket.IO, BullMQ, Redis. Используются паттерны: Outbox, DLQ, Soft Delete, Optimistic Updates, Virtual Scroll.

Богатая функциональность — покрыты практически все сценарии helpdesk: SLA с эскалацией и бизнес-часами, кастомные поля, шаблоны, webhooks, API-токены, SSO, Rules Engine, Telegram-бот, CSAT, Time tracking, Feature flags.

Высокое покрытие тестами — 934 теста, все проходят. Серверные тесты интеграционные (523), клиентские — компонентные (411). E2E расширены до user-flow.

Активная работа над качеством — исправляются баги, ведутся аудиты (Kimi, Qwen, DeepSeek), есть план доработок (Что-доделать.txt) с приоритетами.

Хорошая документация — README, context.txt, AGENTS.md, CHANGELOG.md, PLAYBOOK.md. Описаны этапы, проблемы, решения.

Слабые стороны и критические проблемы
🔴 P0 — критические (ломают CI/Docker)
CI: cmd /c на Ubuntu — не работает, нужно working-directory: server + npx vitest run.

Docker: неправильный stage — build: . без target соберёт nginx вместо node.

check-bundle-size.js: require в ESM — ReferenceError, catch молча глотает.

entrypoint.sh не скопирован — Dockerfile не содержит COPY docker/entrypoint.sh.

Playwright job без сервера — не устанавливает зависимости сервера, нет wait-on.

🟡 P1 — важные
E2E smoke-only — 99% тестов проверяют только видимость заголовков, не бизнес-логику.

Knex → Prisma — два ORM, 3 файла миграций на Knex, мёртвый вес.

Prisma в dependencies — CLI тянет 100+ МБ в prod, нужно в devDependencies.

Двойная валидация — zod + express-validator, выбрать один.

k6: dev-login на каждой итерации — тестируется логин, а не бизнес-логика.

JWT в localStorage — XSS-вектор, для корпсистемы лучше httpOnly cookie.

Coverage 71% — цель 80%+, пороги равны текущему, не защищают от регресса.

🟢 P2 — после MVP
AI auto-triage, Forms builder, Gamification, 2FA, Marketplace, Multi-tenancy, мобильное приложение, CMDB, ITIL, On-call, Voice/Video, Compliance, Status page, Visual regression, npm audit.
